# Eastern Mysticism Archive — Strategic Plan & Execution Guide

## 0. Project Identity

### Working Project Name
**Eastern Mysticism Archive**

Alternative names:
- Ancient Eastern Mysticism Archive
- Chinese Esoteric Culture Database
- Taoist Symbols & Folklore Archive
- Eastern Occult & Folklore Database

### Core Concept
Build an English-language database website about Eastern mystical culture, focusing on:

- I Ching / Yijing
- Taoist symbols
- Taoist talismans
- Feng shui
- Chinese folk beliefs
- Yin virtue / hidden merit concepts
- Luban Book legends
- Funeral taboos
- Ghost month traditions
- Spirits, deities, symbols, rituals, myths
- Cultural meanings behind jade, Guanyin, Buddha pendants, charms, and amulets

This is not a fortune-telling service, spell-casting service, religious service, or scam-style metaphysics site.

The correct positioning is:

> A cultural, symbolic, historical, and folklore research archive for Western readers interested in Eastern mysticism.

---

## 1. Strategic Positioning

### Correct Positioning
The site should feel like:

- A digital archive
- A cultural museum
- A folklore encyclopedia
- A symbolic database
- A mysterious but credible research guide

### Incorrect Positioning
Avoid positioning the site as:

- A spell-casting website
- A curse service
- A “master” service
- A medical/healing service
- A get-rich metaphysics product site
- A fake occult authority

### Tone
The tone should be:

- Mysterious
- Respectful
- Culturally grounded
- Research-based
- Accessible to Western readers
- Not overly academic
- Not fake-supernatural

Recommended wording style:

> “In Chinese folk belief, this symbol was traditionally associated with...”

Avoid wording like:

> “This talisman will definitely bring wealth.”

---

## 2. Core Strategic Goal

The long-term goal is not simply to publish random articles.

The real goal is to build:

> A structured personal knowledge database that can continuously generate SEO pages, Pinterest content, YouTube scripts, and eventually cultural product pages.

The database is the real asset.

The website is only the public-facing layer.

## 4. Project Risk Boundaries

### 4.1 Compliance Boundary
Avoid:

- Guaranteed spiritual results
- Medical/healing claims
- Curse services
- Spell-casting services
- Exorcism services
- “Guaranteed wealth” claims
- Fake religious authority
- Exploitative fear-based selling

### 4.2 Cultural Boundary
Respect the traditions.

Do not mock, distort, or over-sensationalize sacred or folk traditions.

Use phrases like:

- “According to folk tradition...”
- “Historically associated with...”
- “In Taoist symbolic systems...”
- “In some regional beliefs...”

### 4.3 Commerce Boundary
If selling products later, describe them as:

- Cultural jewelry
- Symbolic accessories
- Decorative art
- Heritage-inspired objects
- Traditional motif products

Do not describe them as:

- Guaranteed luck products
- Guaranteed protection tools
- Curse-removal items
- Medical healing products

## 7. Reliable Source Strategy

This project must not rely only on AI-generated content.

The content pipeline should be:

```text
Original source material
↓
Source notes
↓
Structured database entry
↓
SEO article/page
↓
Pinterest/YouTube derivative content
```

### 7.1 Primary Source Types

#### Chinese Classical Sources
Potential source areas:

- Daoist texts
- Yijing / I Ching
- Shanhaijing
- Liaozhai Zhiyi
- Folk ritual manuals
- Regional folklore records
- Funeral custom records
- Local gazetteers
- Symbolic dictionaries

Important note:
Use these as cultural source material, not as supernatural proof.

#### Academic Sources
Use academic references for authority.

Search topics:

- Chinese folk religion
- Taoist talismans
- Daoist ritual
- Chinese funeral customs
- Feng shui history
- Chinese amulets
- Jade symbolism
- Ghost month traditions
- I Ching symbolism

Good source channels:

- Google Scholar
- JSTOR
- university PDFs
- museum archives
- academic books
- open-access journals

#### Museum / Archive Sources
Useful sources:

- The Met
- British Museum
- Smithsonian
- Asian Art Museum
- National Palace Museum
- Chinese museum archives
- university digital collections

These are especially useful for jade, talismans, ritual objects, seals, amulets, and religious art.

#### Contemporary Cultural Sources
Use carefully:

- Reddit discussions
- Quora questions
- YouTube comments
- forums
- modern blogs

These are useful for discovering Western curiosity and keyword angles, but they are not authority sources.

## 8. Personal Markdown Database Strategy

### 8.1 Why Markdown Database
A Markdown database is enough for the first stage.

It requires:

- No server database
- No Supabase
- No MongoDB
- No complex backend
- No extra hardware

It works well with:

- Next.js
- GitHub
- Vercel
- AI-assisted editing
- SEO pages
- version control

### 8.2 Recommended Folder Structure

```text
eastern-mysticism-archive/
├── app/
├── components/
├── content/
│   ├── talismans/
│   ├── symbols/
│   ├── feng-shui/
│   ├── folk-beliefs/
│   ├── rituals/
│   ├── spirits/
│   ├── ghosts/
│   ├── forbidden/
│   ├── i-ching/
│   ├── jade/
│   ├── buddhist-objects/
│   └── glossary/
├── raw-materials/
│   ├── books/
│   ├── pdfs/
│   ├── screenshots/
│   ├── notes/
│   └── source-links/
├── public/
│   └── images/
├── lib/
└── docs/
```

### 8.3 Raw Materials vs Published Content

#### raw-materials/
This folder stores original research material:

- PDFs
- screenshots
- copied notes
- source links
- Chinese notes
- rough translations
- academic references

#### content/
This folder stores cleaned, structured, publishable Markdown entries.

Never mix raw messy notes with publish-ready content.

## 9. Markdown Entry Template

Each database entry should use frontmatter.

```markdown

title: "Five Thunder Talisman"

```

## 15. Step-by-Step Working Mode

This project should follow the same execution rhythm as SleepPilatesTools:

1. Assistant gives one concrete task.
2. User executes it locally.
3. User reports terminal output / screenshots / result.
4. Assistant checks result.
5. Assistant gives the next task.

Do not skip ahead.

Do not open many tasks at once.

Do not build complex systems before the basic project runs.
