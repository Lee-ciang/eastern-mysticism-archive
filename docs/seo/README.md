# Eastern Mysticism Archive SEO Operating System

**Version:** 1.0  
**KAPF stage:** Performance Validation  
**Status:** Active operating documentation

## Introduction

The SEO Operating System, or SEO OS, is the permanent documentation framework for managing organic search performance across Eastern Mysticism Archive.

It connects strategic rules, current Search Console evidence, prioritized execution, repeatable operating procedures, and monthly reporting. Its purpose is to make SEO work scalable, traceable, and consistent over multiple years.

SEO OS is designed around the Knowledge Asset Production Framework. During Performance Validation, the project prioritizes pages and clusters that Google is already testing rather than expanding content based on assumptions.

## Operating Principles

- Search Console evidence guides priorities.
- Existing successful clusters are strengthened before unrelated expansion.
- Traffic quality matters more than content volume.
- SEO decisions improve the knowledge graph, not only individual pages.
- Every optimization has a documented reason, scope, validation result, and review date.
- Operational documents are updated deliberately rather than rewritten casually.

## Documentation Map

### [SEO Decision Rules](SEO_DECISION_RULES.md)

The permanent decision framework for SEO work.

Use it to determine:

- Which evidence should control a decision.
- Whether to optimize an existing asset or create a new one.
- How SEO work follows the KAPF roadmap.
- Which technical and editorial guardrails must be preserved.
- How to avoid speculative or quantity-driven expansion.

This document should change infrequently. Amend it only when the project adopts a durable new decision principle.

### [Star Pages](STAR_PAGES_2026-07-24.md)

The current classification of pages and clusters receiving meaningful Google testing.

Use it to determine:

- Which pages have the strongest current opportunity.
- Which tier should receive optimization resources first.
- Which emerging pages belong in the monitoring queue.
- What general optimization goals apply to each tier.

Star Pages are evidence-driven and time-sensitive. Create a dated successor when the tier structure materially changes rather than rewriting historical snapshots.

### [Next Optimization Queue](NEXT_OPTIMIZATION_QUEUE.md)

The ordered execution queue derived from current performance signals.

Use it to determine:

- Which cluster should be optimized next.
- Which tasks and completion criteria apply.
- What dependencies should be reviewed before implementation.
- When a priority is ready to move into active work.

Update or replace the queue when work is completed or new evidence materially changes priority order.

### [SEO Playbook](SEO_PLAYBOOK.md)

The practical handbook for recurring SEO situations.

Use it when:

- Google begins testing a page.
- Impressions change suddenly.
- Click-through rate falls.
- Rankings improve or decline.
- The team must choose between optimization and new content.
- A monthly SEO review is due.
- A KAPF phase decision must be made.

The playbook defines Standard Operating Procedures, required evidence, actions, validation, and records.

### Monthly Reports

Monthly reports are stored under:

`docs/seo/reports/YYYY/MM/`

Reports preserve:

- Search Console observations.
- Star Page changes.
- Optimization decisions.
- Completed work.
- Technical or editorial risks.
- Results requiring continued monitoring.
- Priorities for the next review cycle.

Reports are historical records. Once finalized, correct factual errors transparently rather than rewriting earlier conclusions to match later results.

## Document Ownership

The project owner retains final authority over strategy, publishing, and priority changes.

Planning collaborators may analyze data, prepare recommendations, and maintain documentation. Implementation collaborators may execute approved changes and validation. No collaborator should bypass the decision rules or silently alter historical SEO records.

## Maintenance Rules

- Review the optimization queue during every monthly SEO review.
- Review Star Page tiers when Search Console evidence changes materially.
- Review this index whenever a permanent SEO document is added, renamed, or retired.
- Update the playbook when a recurring situation requires a new stable procedure.
- Preserve dated reports and Star Page snapshots as historical evidence.
- Verify document links after every SEO documentation change.
